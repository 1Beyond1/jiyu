更新：2026-10-20。项目名称：集屿 / Jiyu（用户已确认）。

## 用户目标

把微信等渠道零散收到的文件，转为一个链接集中收集，按任务与提交人整理。部署到自己的 VPS；存储可选择本地或网盘；通过批量工具和悬浮 AI 减少重复劳动。

用户已确认简约高级、参考 Claude 的暖纸色、炭灰文字、陶土点缀与衬线标题。当前按「继续直至第一版可用」推进本地存储 MVP，前端接入真实服务；原型浏览器记录与正式数据隔离。

## 控制目录增长

1. 不创建 `v2/`、`final/`、`backup/` 等源码副本。历史依靠 Git，当前界面作为首个版本纳入管理；推送按用户授权执行。
2. 不提前搭空的 monorepo。真正开始后端时再增加 `server/`，复用 TypeScript 类型，先保持单仓库。
3. `node_modules/`、`dist/`、`.cache/`、`.artifacts/` 是可再生内容。截图与临时样本仅进 `.artifacts/`；npm 缓存可随时清理。
4. 开发依赖仅在本地/构建阶段使用。部署只打包应用构建结果与正式服务依赖，不把 npm 缓存和原型截图带上 VPS。
5. 正式版数据放独立挂载，例如 `/var/lib/jiyu/`；与应用发布目录分开。数据库、上传和备份不进 Git 或 Docker 镜像。
6. 日志轮转、临时上传定期清理、单任务/全局配额、回收站保留期、备份保留上限需要在 P1/P2 实现并验证。
7. 增加依赖前说明用途。简单状态用 React；简单弹窗用原生 dialog；本阶段无 UI 大组件库、状态库或路由库。

## VPS 上线时需要配置

- 风格、信息密度与任务字段是否适合实际使用。
- VPS 系统、配置、域名与 HTTPS 入口。
- 真实需求中的文件大小、单次提交数量、并发规模和保留时长。
- 最常用的网盘具体是哪家，以及是否有可用的官方授权/API。
- 上传人是否匿名，是否需要密码、名单与提交回执。

第一版默认单管理员、匿名持令牌提交，单 VPS Linux + Docker；具体上限可通过环境变量和任务规则调整。支持回执，不加入名单与提交密码。实际 VPS 尚未提供访问资料，本轮交付可在本机运行的服务和完整部署配置，不声称已经部署到用户 VPS。

## 任务管理补全（2026-10-20）

- 任务标题进入独立详情地址 `#/collections/:id`，刷新后仍能定位；详情展示收集进度、规则和该任务的文件。
- 新建与编辑共用表单，可设置单文件上限（1–1024 MB）和单次数量（1–100 个），编辑保留任务 ID、收集链接和已有记录。旧浏览器记录自动补齐 100 MB / 20 个的默认规则。
- 暂停、结束、重新开放均有确认，操作写入最近动态。已过期任务显示「已截止」，延长日期后才可恢复接收。
- 截止时间统一为所选日期 UTC+8 当天结束；新建默认截止日期为当前日期后 7 天。目标份数仅用于进度，不是提交配额。
- 选文件和提交前共用规则校验；阻止超量、超大、格式不符、空姓名与已关闭任务的提交。仅保存元数据的原型边界保持不变。
- 使用 Node.js 原生测试运行器验证格式、时区截止边界、暂停/结束、大小边界和数量限制，无新增依赖；GitHub CI 增加 `npm test`。

# 集屿：独立本地体验包

当前工作区 0.4.0-dev.0 的参赛候选快照，尚非正式 Release。MIT 许可与原作者声明见根目录 LICENSE。包内没有账号、默认密码、私密回执、模型 Key、数据库或已收文件。所有 examples/submission 文本为原创公开合成材料。

## 启动与停止

1. 安装 Node.js 24.11 或更新的 24.x 版本（含 npm）。解压 ZIP 后，进入有 package.json 的 jiyu 目录。Windows、Linux 或 macOS 均沿用同一命令；本轮实际验证环境以包外材料清单为准。
2. 执行 `npm ci --omit=dev`。**首次需要联网下载锁定依赖**，不包含 node_modules，也不是完全离线包。前端已构建在 dist，不需要构建才能体验。
3. 执行 `node scripts/review-start.mjs`，打开 `http://127.0.0.1:3014/`。若端口占用，用 `node scripts/review-start.mjs 3015` 选择其他空闲端口，后续始终用同一地址。脚本仅监听本机，不自动开放公网。
4. 首次读取本包 `.review-data/setup-token`：PowerShell 用 `Get-Content .review-data/setup-token`，Linux/macOS 用 `cat .review-data/setup-token`。网页填写该口令、合成显示名称与自行设置的至少 12 位密码，确认后创建管理员；登录名 admin。口令仅本机首次初始化使用，勿录入公开视频。后续启动原目录会保留原数据，不重置。
5. 按 Ctrl+C 停止。数据位于解包目录的 `.review-data`，备份目录 `.review-backups`；不要把使用后的目录重新打包或公开。包本身保持无数据，重复解包到新目录获得新实例。关闭服务前留存自己需要的完整备份。

若要核查源码：执行 `npm ci` 后 `npm run build`；包中保留当前源码、唯一锁文件与配置。PDF/OCR 原生工具不随 ZIP 内置，TXT 合成主线不需要它们；其部署依赖见原项目部署文档。联网模型和网盘需要使用者自己的合法授权，当前包默认没有模型与云端连接。

## 五分钟评审路径

1. 发起新收集，先看“一句话材料草稿”显示模型尚未配置。不要把模板创建说成模型生成。选择“社团作品征集”模板，将标题改为“集屿公开合成演示”，预计份数 2，截止日期选未来日期。
2. 下一步确认 TXT 格式，名单填写 DEMO-01、DEMO-02，各占一行；两项必需、一项选填保持模板。确认后点击原“创建收集”。
3. 打开提交页，新浏览器或手机窄视口输入合成提交者与 DEMO-01。按“上传 报名表”“上传 作品说明”选择 examples/submission 中对应的两份 TXT，提交并**自行私下保存回执**。本机链接只供本机浏览器，不宣称实体手机可直接访问。
4. 管理端刷新“材料收齐与核对”：DEMO-01 两项待人工核对，DEMO-02 缺项。查看 DEMO-01，选作品说明，人工选“需补充或纠正”，说明填写 EXPECTED.json 中的 manualReviewNote，保存。
5. 返回原提交成功页，直接查看本批核对进度与补充说明；可点“更新核对进度”。已刷新页面时，点“已经交过？查询回执 / 替换文件”，原浏览器已保存的回执会自动查询；换浏览器须导入保存的私密回执。选择“按说明替换本批文件”，按材料卡选择“补充后的报名表.txt”“补充后的作品说明.txt”，明确替换后提交。原两份进入回收站，新两份应待人工核对，不继承旧结论；旧回执不再代表当前批次。
6. 管理端刷新并导出材料台账。CSV 应有表头加 6 个材料行，DEMO-01 两项待核对、DEMO-02 两项缺项、两人选填未交，未自动判定全部通过。文件详情实际下载应与合成原文一致。

当前材料矩阵读取授权服务端状态，按规则 token、文件版本与摘要绑定当前快照；文件或规则变化时先同步再处理。手机 AI 入口在顶部，提交按钮位于普通文档流。实际单文件 / 单次上限取服务器限额与任务规则的较小值，本地体验包默认单次 32 MB。AI 预核对要求读取正文和逐次授权；未配置模型时明确不可调用。包不含伪造模型响应或“演示 AI”开关。

其他正式提交条件、外部访问与作者/团队填写见 REQUIREMENTS.md。实际包校验、历史影片标注及未完成项见包外材料清单；ZIP 存在不代表已经满足全部赛事要求。

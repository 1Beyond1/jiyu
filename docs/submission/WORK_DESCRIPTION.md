# 集屿：让零散文件，有序归屿

## 目标用户、场景与任务

面向独立组织活动、课程、报名或项目交付的收件人。过去，文件散落在聊天窗口，收件人反复下载、改名、核对缺件，再通知对方重交。集屿把这些动作放进一个可部署在个人 VPS 的中文工作台：发起人列材料，提交者通过一个链接上传，双方按任务和本人回执追踪后续变化。

当前主线是社团作品征集：报名表和作品说明必需，补充附件选填，按明确报名编号识别人。展示使用原创合成 DEMO-01 / DEMO-02，既不冒充真人试用，也不以同名推断身份。

## 当前可使用的结果与特色

- 发起人用模板或人工确认后的表单创建任务；每项材料独立定义必需性与要求。手机窄视口按材料卡选择文件，断点续传与批次回执沿用真实服务。
- 逐人逐项展示“缺项、待人工核对、需补充、核对通过、旧核对过期”，区分收到文件和人工通过。内容相同的重复文件不能凑齐不同必需项。
- 人工补充说明可由本人私密回执查看；本人替换本批后，旧文件进入回收站，新文件不继承旧批准。材料规则或文件版本变化也会令原核对结论失效。
- 有出处的 AI 材料预核对已实现：先查看本次授权摘录与未读范围，返回建议须引用同一文件精确位置，最终仍由人查看原文并保存。当前没有产品模型 API，本包不能展示真实语义输出，不声称模型效果、准确率或节省比例。
- 一句话材料草稿已接入原创建流程，模型草稿需逐项人工确认、澄清后再创建。未配置模型时显示不可生成，模板路径继续可用。
- 原有文件管理、命名与撤销、查重、回收站、ZIP 归档、备份恢复继续存在。本次演示只声明实际验证的材料收集闭环，不以本地操作代替公网部署或长期负载验证。

## 既有作品的本期实质更新

既有基础是文件收集与批量整理。本期增加逐项材料定义、私人应交名单与逐人矩阵、绑定规则和文件版本的人工核对、本人回执补交/替换、有精确出处与人工确认的 AI 预核对、经人工澄清的一句话材料草稿。前端完成暖珊瑚视觉与发起人 / 提交者流程重写，后端新增同源材料状态读取和公开错误下一步提示。代码在包内可检查；模型能力的工程实现与未完成的真实模型验证分别披露。

## 模型、工具、第三方与数据来源

- 前端 React + TypeScript + Vite；服务端 Node.js 24 + Fastify；元数据 SQLite，本地文件使用随机存储键与 SHA-256。依赖与准确版本以 package-lock.json 为准，应用 MIT，第三方依赖保留各自许可。
- 开发辅助工具：当前工作记录使用 Codex，前端由 Claude 辅助重写；这与产品运行时调用的模型分别披露，不将开发工具的能力作为产品模型实测。具体工具模型版本和开发费用未核实，提交前由作者按真实情况补充。
- 模型适配支持用户合法配置的 Responses / Chat Completions 兼容接口。**当前主要模型名称：未配置；本轮真实模型调用：0。** 不将开发测试中的依赖注入响应作为产品模型结果，不收集或寻找其他项目密钥。
- 公开演示输入仅为本包原创合成 TXT，不含姓名、学校、联系方式、正式上传材料或受限官方原件。包中无模型 Key、运行数据库和私密回执。
- 所有核对状态由明确规则与人工操作决定；AI 只能建议，不能自行批准、删除或外发更多材料。外发正文须使用者审阅并逐次授权；本地主机验证不等于实体手机、支付宝运行环境或 VPS 已验。

# 技术选型与架构建议

更新：2026-10-21。本地存储 MVP 已交付；当前开发版增加模型辅助、正文整理、成员、备份、断点续传和远端存储适配，尚未发布新版本。夸克原生登录仍未完成，提供自托管 WebDAV 桥接。

## 第一版实施决策

### 完整工作台实施（2026-10-20，开发中）

- 继续使用同一个 Fastify / SQLite 服务。schema 3 保存分片上传、工作台成员、备份计划和后台处理状态；旧管理员兼容迁移，升级前保留离线备份。
- 断点续传采用固定 4 MiB 分片、独立上传凭证、分片 SHA-256 和原子批次提交。临时正文放 `chunks/`，24 小时过期，预留整批容量；重选文件时逐片比对，避免拼接不同版本。原 multipart 接口共享容量预留边界。
- 自动备份使用 SQLite 在线快照，再从快照读取不可变正文引用。清单最后写入，保留策略只清理专用备份目录内完整且可识别的备份；服务端不会在线清空回收站正文。
- 成员权限采用单工作台的管理员 / 编辑者 / 只读成员，服务端逐请求鉴权；不引入多租户。
- 网盘连接使用服务端加密凭证和可恢复传输记录，连接测试与真实授权状态分开。WebDAV / S3 使用标准协议，百度 / OneDrive / Google Drive 使用官方授权协议；夸克仅支持自托管桥接，未授权时不显示已连接。
- 预览与正文索引只处理明确支持的类型；OCR 在本机运行。正文交给外部 AI 需要额外明确授权，原有元数据授权不自动扩大。

正文检索使用 SQLite [FTS5 trigram](https://www.sqlite.org/fts5.html)，支持中文子串；两字查询使用受限结果的线性匹配。DOCX 沿用已有 `yauzl` 读取器并调整为正式依赖，只读取限定大小的 `word/document.xml`，拒绝实体声明，不解压到文件系统。PDF 使用 Poppler，OCR 使用 [Tesseract CLI](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html)，子进程不用 shell，限定线程、时间、页数、像素及输出；识别后的文本只在本机 SQLite 中索引。容器增加原生工具测试，宿主机未安装时会明确报告缺失，不用模拟结果替代识别。

### 远端连接与传输实施

- schema 4 保存连接配置、加密凭证和持久传输队列。仍先在本机可靠接收，再复制到用户明确选择的云端；界面分别显示接收和云端同步结果。此阶段保留完整本机副本以兼容预览、打包和完整备份，不能声称节省 VPS 正文空间。
- WebDAV 使用原生 HTTPS 的 MKCOL / PUT / GET，S3 使用 SigV4 与单对象上传（现有单文件上限低于 5 GB），不增加 SDK。自定义地址固定 DNS 并拒绝内网，凭证只在保存时写入且不回显。
- WebDAV / S3 连接测试只对随机测试对象写入、读回校验和删除；原生网盘连接测试只核验账号授权，实际写入权限与配额在传输时确认。连接配置变化使原测试状态失效。传输使用带文件 UUID 的确定路径与重试记录；百度校验分片 MD5 和合并结果，其他适配读回 SHA-256。
- 百度依据其开放平台公开 SDK 实现授权与分片接口；应用资格和用户授权由平台决定，不使用官方示例中的临时体验密钥。夸克官方 Agent CLI 限定运行环境，不能通过伪装 Agent 或复制公共签名参数当作本产品的应用资格；继续核对可用于独立 VPS 应用的授权方式。
- 对独立应用授权未取得的平台，提供明确标注的自托管 WebDAV 桥接：用户先在自己的 OpenList 连接对应网盘，再把该挂载目录的 HTTPS WebDAV 接入集屿。集屿不使用公共令牌刷新站、不代存浏览器 Cookie，也不把桥接校验描述为该平台原生登录已完成。此为可用的转存路径，原生登录接入仍属于未完成项。
- OneDrive 与 Google Drive 使用自有 OAuth 网页应用，状态随机且只能使用一次，PKCE 验证交换过程，回调绑定发起管理员与连接版本；换账号后撤销旧连接的可用标记。OneDrive 使用 Files.ReadWrite / offline_access，Google 使用 drive.file，仅操作应用可见文件。原生适配支持分片上传、确定文件名去重和 SHA-256 读回，令牌在服务端刷新并加密保存；没有用户账号实测时，仅记录为协议验收。

- 单仓库增加 `server/`，Fastify 提供同源 API 和构建后的前端，Node.js 24 直接执行 TypeScript，不另加运行时转译器。
- SQLite 使用 Node.js 内置 `node:sqlite`，先不引入 Drizzle；显式事务和 schema 版本维护结构。文件正文流式写入独立数据目录，随机存储键与显示名称分离，记录 SHA-256。
- 仅新增 Fastify、multipart、static、cookie、rate-limit 官方组件，分别负责 HTTP、流式上传、静态页面、会话 cookie 与限流。认证、哈希、文件和 SQLite 使用原生 API。
- 首次初始化需要数据目录中的一次性口令；管理员密码使用 scrypt，随机会话仅保存哈希，cookie HttpOnly / SameSite，写操作使用会话 CSRF 令牌及固定 Origin 校验。
- 分享使用独立随机令牌，公开接口不返回其他提交者或文件列表。服务端重复校验状态、截止、数量、容量、配额；批次先落临时文件，再事务提交，失败清理，重试使用幂等键。
- 第一版批量重命名在 SQLite 事务内原子完成，不移动文件正文；保留审计与撤销映射。回收站仅软删除，释放空间需明确清理。
- 备份/恢复通过停机 CLI 完成：互斥数据目录锁、数据库与文件一致快照、清单哈希校验、恢复到新目录，不覆盖现有目录。上线使用 Docker Compose + Caddy，数据单独挂载。
- 验收以真实 HTTP 集成测试覆盖认证、上传下载字节一致、权限隔离、限额、重复提交、重命名、重启持久化及备份恢复；浏览器检查实际操作入口。

实现依据：[Node.js 24 SQLite API](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)、[Fastify multipart](https://github.com/fastify/fastify-multipart)、[Caddy 请求体限额](https://caddyserver.com/docs/caddyfile/directives/request_body)、[Compose 健康检查启动顺序](https://docs.docker.com/compose/how-tos/startup-order/)。Node 内置 SQLite 在当前 24.x 运行时仍有实验性提示，限定主版本并通过 CI 验证升级。

## 推荐方案

| 层 | 选择 | 适合本项目的理由 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite | 工作台交互多，React 便于复用任务、表格与助手；TS 约束元数据和操作；Vite 可生成静态资源，由反向代理或后端提供 |
| 样式 | CSS 设计变量 + Lucide 图标 | 便于确定个人风格，避免先引入大组件库；颜色、留白与密度集中维护 |
| API | Node.js + Fastify + TypeScript | 与前端共用语言；可通过 multipart 插件流式处理上传，校验与权限集中在服务端 |
| 元数据 | SQLite（Node 内置 API） | 单 VPS 起步，无独立数据库服务；保存任务、元数据、操作与作业记录。文件原件在独立目录，提取文本保存在本机索引 |
| 文件 | LocalStorageAdapter → S3/WebDAV → 网盘授权适配 | UI 和业务不依赖单一存储商；逐个接入、测试与处理限制 |
| 批处理 | 数据库持久作业 + 服务内串行队列 | 转存与正文处理在后台运行；记录失败与重试，服务重启后恢复。改名使用短事务 |
| 部署 | Docker Compose + Caddy | 一个应用服务配反向代理；HTTPS 与持久卷边界清晰，适合单台 VPS |
| AI | 服务端模型适配层 | 自选模型服务；凭证不发前端。默认只发送经明确选择的必要元数据 |

Vite 的定位与 Node 版本要求见[官方指南](https://vite.dev/guide/)。React 官方也将 Vite 列为从头构建 React 应用的工具选择之一，详见[React 文档](https://react.dev/learn/build-a-react-app-from-scratch)。本机采用 Node.js 24，具体依赖版本由锁文件固定。

Fastify 的上传能力参考[官方 multipart 插件](https://github.com/fastify/fastify-multipart)。正式版必须显式设置每文件大小、文件数、字段数和整请求总字节限制；消费上传流，限制并发，不把大文件整块读入内存。

SQLite 适合服务端管理的中小规模网站，但同一时刻只支持一个写者，参见[官方适用场景](https://www.sqlite.org/whentouse.html)。启用 WAL、短事务和合理的忙等待；多副本或持续高写入时迁移 PostgreSQL。Drizzle 便于统一查询与迁移定义，但迁移仍需验证，不能假设换数据库无需修改。

## 为什么现在不选其他方案

- **Next.js**：如果后续需要重内容展示、SEO 或服务端渲染可以考虑；当前是以登录后操作为主的工具，静态前端配明确的 API/worker 边界更直接。此为项目需求判断，不代表 Next.js 无法自托管或上传。
- **NestJS**：大型团队与复杂领域可受益，本项目起步阶段会增加更多约定和样板。
- **微服务 / Redis / 单独 PostgreSQL**：当前需求不需要先维护多个基础服务。满足单机闭环后再按实际瓶颈扩展。
- **无差别接入所有网盘**：各平台的开放权限、限速和服务区域不同，不能承诺网页登录一次就都能稳定接入。优先官方 OAuth、S3、WebDAV。

## 存储边界

### 批量下载实施决策

- 归档作为现有服务的只读功能，不增加数据库表、worker 或磁盘缓存。管理员先生成短期计划并预览路径，再通过同源鉴权链接流式下载，浏览器直接接收，不使用前端 Blob 缓存整个包。
- Node.js 的 zlib 提供压缩算法，不提供 ZIP 容器写入。增加小型 [yazl](https://github.com/thejoshwolfe/yazl) 流式写入器（支持 UTF-8 与 ZIP64），测试使用独立 `yauzl` 读取器验证正文。只打包、不重新压缩已有素材，保持低 CPU 占用。
- 计划支持平铺、按任务、按提交人、任务/提交人四种布局。归档路径独立规范化，处理非法字符、路径穿越、设备保留名、超长名称及大小写重名；原文件与数据库名称不变。
- 每次最多 500 个文件、10 GiB 原始内容；最多 2 个同时下载、20 个短期计划，计划绑定登录会话、10 分钟内开始、只能使用一次，传输最多 30 分钟。状态可查询，失败可重新生成计划。计划与 ZIP 不写磁盘，服务重启后失效。
- 开始下载前重新校验文件状态、名称、大小及存储键；流式读取时核对 SHA-256，文件缺失、损坏或连接中断时停止输出并释放资源。公开收集令牌不能创建或下载归档。

计划接口只围绕 `putStream / getStream / stat / delete / health` 等必要能力。存储键采用随机 ID，显示名称独立存元数据，重命名优先只修改元数据，避免对象存储复制大文件。所有写入需校验任务权限与配额。

当前所有文件先写入 VPS 本地持久卷，按任务配置复制到远端。WebDAV / S3、百度及 OneDrive / Google Drive 已有协议适配，待真实账号联调；夸克仅桥接。rclone 可以作为后续后台传输桥接候选，已有多种[官方列出的后端](https://rclone.org/docs/)，但不会把完整 rclone 管理 API 暴露给上传者，也不把“支持某后端”等同于已完成产品集成。

## 文件安全的实现要求

不是“用了网盘就保证安全”。正式版需落实并测试：

- 管理端身份认证，短期会话，CSRF 防护；收集页只持有高熵、可撤销、限期的上传令牌，不允许列出其他人的提交。
- 服务端重复校验截止时间、文件格式、数量和容量；上传扩展名不等同于内容类型校验；随机存储名，防止路径穿越。
- 上传目录不可执行，下载走鉴权接口，控制 Content-Type/Disposition，避免把用户 HTML/SVG 直接作为可信页面执行。
- 限流、整请求体限额、流式写入、临时文件清理、失败重试与内容校验。病毒扫描按实际需求引入。
- TLS；磁盘/对象存储加密与加密密钥独立管理；OAuth 凭证在服务端加密保存。密钥不能写入 Git、前端环境变量或日志。
- 数据库与文件一致的备份策略、保留上限和恢复演练。备份不与唯一原文件共用一个故障点。
- 批量变更先生成计划，检查重名与权限，确认后执行，写入审计记录与可恢复映射。

## AI 的权限边界

### v0.3 实施范围

- 实现可配置的 OpenAI Responses / Chat Completions 兼容接口，无新增 SDK。服务端使用原生 HTTPS 请求，固定解析协议并限制响应大小、DNS 5 秒 / HTTP 45 秒超时、并发及每日调用次数；默认关闭，不绑定或推荐具体模型。
- 管理员可在设置里保存服务地址、模型和 API Key。Key 使用 AES-256-GCM 加密保存在 SQLite，随机主密钥位于数据目录的 `secrets.key`，权限 0600，接口不回显。完整备份增加主密钥校验与恢复，旧备份继续支持。
- 每次请求由用户明确选择最多 30 个文件，确认发送当前问题、文件名称/大小/任务名；提交人需另行勾选。服务器重新读取作用范围，回收站或未知文件不发送。正文摘录须单独勾选授权，总计最多 8000 字符；收集令牌不进入模型上下文。
- 授权绑定当时的设置版本；另一页面更换模型、地址或凭证后，旧授权不能调用新配置。问题独立发送，不将面板历史隐式带入下一次请求。
- 自定义地址仅允许 HTTPS，DNS 解析后拒绝内网/回环/保留地址并固定连接地址，不跟随重定向。只在注入的测试传输中使用本地模拟响应，不放宽生产规则。
- 模型返回文字、命名或标签建议。建议在服务器检查文件别名、扩展名、非法路径、重名及标签上限，保存操作编号；用户预览确认后复用现有事务与撤销。模型不能调用删除、上传、外发或任意命令。
- 调用日志只保存状态、模型、文件数量、用量和时间，不保存问题、回复、文件正文或密钥。调用次数上限包含失败尝试，避免重试绕过限制；模型费用取决于用户选用的服务商。

悬浮面板是操作入口，不自动获得整个磁盘和网盘权限。模型给出结构化操作计划，服务端按白名单工具重新鉴权、校验路径和作用范围，前端预览后确认。文件文本与模型输出均视为不可信内容；不能把文件里的指令当系统命令。删除、外发、跨存储搬移应有明确的单独确认。

默认以文件元数据辅助命名。涉及正文识别时需另行设计开关和授权范围，当前未实现。接口协议依据 [Responses 迁移说明](https://developers.openai.com/api/docs/guides/migrate-to-responses) 与 [JSON 输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)；JSON 模式不替代服务端结构校验。

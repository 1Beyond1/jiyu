# 集屿部署与运维

当前发布版本为 v0.3.0（MIT）。部署建议检出 `v0.3.0` 标签后构建；`main` 用于日常开发，不保证始终对应同一个版本。日常推送只同步代码与执行 CI，发布版本仅在用户明确要求时进行。

适合单台 Linux VPS、一个管理员和少量并发收集。需要已安装 Docker Engine 与 Compose 插件，域名解析到 VPS，放行 TCP 80/443（可选 UDP 443）。数据库使用本地文件系统，不放 NFS；单个数据目录仅启动一个应用进程。

## 本机运行

安装 Node.js 24.11+（24.x），在仓库根目录执行：

```sh
npm ci
npm test
npm run build
npm start
```

打开 `http://127.0.0.1:3000`。首次页面需要初始化口令：Windows 执行 `Get-Content data/setup-token`，Linux 执行 `cat data/setup-token`。口令只用于创建管理员，完成后文件自动删除。设置至少 12 字符的密码，妥善保存在密码管理器中；不会生成默认账号或默认密码。原型的浏览器演示数据不会导入。

开发前后端时，在第一个终端将 `JIYU_ORIGIN` 设为 `http://127.0.0.1:5173` 后运行 `npm run server:dev`，第二个终端运行 `npm run dev`。Vite 将 `/api` 代理到 3000；Origin 必须与访问页面完全相同。正式环境用后端直接提供 `dist/`，无需 Vite。

## VPS 部署

```sh
git clone https://github.com/1Beyond1/jiyu.git
cd jiyu
cp .env.example .env
```

编辑 `.env` 中的 `JIYU_DOMAIN` 和 `JIYU_ORIGIN`，例如分别为 `files.example.com` 和 `https://files.example.com`，然后：

```sh
docker compose up -d --build
docker compose ps
docker compose exec app cat /data/live/setup-token
```

打开域名，输入上一步的初始化口令并创建管理员。Caddy 自动申请 HTTPS 证书；应用端口 3000 不映射到公网。不要在 `.env` 中填写管理员密码，也不要把初始化口令发给提交者。初始化后创建收集、分享链接，使用另一台设备验证上传，再从管理端下载检查。

数据位于 Compose 命名卷的 `/data/live`，备份位于独立卷 `/backups`。升级、重建容器保留这些卷。**不要使用 `docker compose down -v`**，它会删除卷。需要迁移服务器时，必须迁移完整备份，不能只复制 Git 仓库。

## 配额与运行限制

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `JIYU_ORIGIN` | 本机 `http://127.0.0.1:3000` | 必须与外部页面地址相同；HTTPS 时启用 Secure cookie |
| `JIYU_QUOTA_MB` | 10240 | 文件总配额，含回收站，不代表磁盘实际容量 |
| `JIYU_REQUEST_MB` | 512 | 一次上传的文件正文总量上限；请求封装另有 2 MiB 硬限额 |
| `JIYU_DATA_SUBDIR` | `live` | Compose 数据卷中的子目录，可切换到已恢复的新目录 |
| `JIYU_DATA_DIR` | 本机 `./data` | 非 Compose 时指定持久数据目录 |
| `JIYU_HOST` / `JIYU_PORT` | `127.0.0.1` / `3000` | 非 Compose 时的监听地址；不直接开放裸 HTTP 到公网 |
| `JIYU_TRUST_PROXY` | `false` | 仅在应用只允许可信反向代理访问时开启；Compose 内置配置为 `true` |

每个任务另有文件格式、单文件大小、单次数量、任务总容量限制。第一版最多同时处理 4 个上传请求，单次最多 100 个文件，文件总数最多 10000（含回收站）。文件正文不整块读入内存。上传请求最多 10 分钟，失败后保留所选文件可重试；同一个提交编号不会重复保存。

登录尝试每来源每分钟最多 5 次；上传每来源每小时最多 30 次，普通接口每分钟 180 次。Compose 中应用端口不公开，只接收 Caddy 转发，因此显式信任代理提供的客户端 IP。裸机部署默认不信任转发头；开启代理信任时必须限制应用只能被可信代理访问。日志输出不包含令牌、文件名或密码，Docker 日志轮转为每容器 2×10 MB。

## 批量 ZIP 下载

管理员可对选中文件或当前筛选结果生成归档预览，选择平铺、任务、提交人、任务/提交人四种目录结构。下载使用当前显示名称，归档内自动处理非法路径、过长名称、设备保留名和大小写重名，不修改原文件。按提交人分组依据其填写的名称，不代表已验证身份。

每个归档最多 500 个文件和 10 GiB 原始内容，最多 2 个同时传输；创建预览每来源每分钟 12 次，开始下载 6 次。计划保存在内存，最多 20 个，绑定登录会话，10 分钟内开始且只能使用一次，重启后失效。关闭未开始的预览会清理计划，其他已结束计划最多保留 10 分钟；不生成服务器 ZIP 缓存，也不新增数据库表。

ZIP 按需逐个读取文件并核对 SHA-256，只打包、不重新压缩。浏览器直接接收 HTTP 附件，无需前端把整个包读入内存。传输最多 30 分钟，断开、取消、正文缺失或校验失败时释放资源；开始后不支持断点续传，失败需重新生成预览。服务端「已发送」不代表浏览器已保存到磁盘，最终结果以浏览器下载列表为准。

## 模型服务

默认关闭。在管理员设置页填写模型 ID、HTTPS 接口根地址和 API Key，选择 Responses 或 Chat Completions 协议，保存后启用。服务地址不要包含最终的 `/responses` 或 `/chat/completions`；只接受公网 HTTPS 443，不跟随重定向，DNS 解析到内网或保留地址会拒绝。VPS 需允许外部 DNS 与 HTTPS 出站。兼容服务必须支持相应 JSON 输出及输出长度参数，不保证所有兼容商的所有模型都能直接使用。

Key 经 AES-256-GCM 加密保存于 SQLite；随机主密钥位于数据目录 `secrets.key`（Linux 权限 0600），首次保存凭证时生成。不要只备份数据库、单独删除此文件或公开完整备份。备份工具自动复制并校验主密钥，恢复后可继续使用原凭证；缺失时需从完整备份恢复或在设置页重新填写 Key。移除凭证会同时停用模型。

连接测试明确调用一次模型，不发送文件信息，计入次数并可能计费。悬浮面板的每次提问需要确认发送：当前问题、工作台统计，以及最多 30 个选定文件的名称、大小和任务名；提交人默认不发送，需另行勾选。上传令牌与整段历史不会进入模型上下文；正文默认不发送，额外授权的摘录范围见下文。更换服务商必须重新填写 Key；设置变更使旧的发送授权失效。

每次问题最多 1000 字符，最多 2 个同时处理的模型请求；提问每来源每分钟 6 次、测试连接 3 次。默认每天 50 次调用（可设 1–1000），按 UTC+8 重置，失败和取消也计入。DNS 解析最多 5 秒，HTTP 请求最多 45 秒，响应最多 128 KiB。取消不能保证服务商停止计费，次数限制也不等于金额预算，需在服务商账户另设费用上限。

模型只能返回建议。命名方案经过服务端检查，预览确认后才执行，30 分钟有效且只能应用一次；文件状态或名称已变化时会拒绝，成功后可撤销。调用历史仅保留模型、文件数量、状态、用量与时间，不保存问题和回复正文；本机面板关闭后不保留对话。该限制不控制服务商自身的数据保留政策。

## 完整备份

日常可在设置页直接执行在线完整备份，并设置每 6 / 12 / 24 小时或每周自动备份，保留最近 1–30 份。默认关闭自动计划，避免未经配置占满磁盘。Compose 将备份写到独立 `/backups` 卷；直接运行 Node 可通过 `JIYU_BACKUP_DIR` 指定，否则使用数据目录旁的 `backups/`。新快照校验成功后才执行保留策略，手工命名的其他备份不在自动清理范围。

在线备份使用 SQLite 快照中的对象引用复制不可变正文，正文、数据库和凭证主密钥都校验。备份执行期间继续接收上传；新上传若不在该快照内，会进入下一份备份。下面的停机命令仍用于升级前快照与运维。

先停止应用，生成数据库与文件一致的完整快照；Caddy 可以继续运行。备份命令检测数据目录互斥锁，在线运行会拒绝。

```sh
docker compose stop app
docker compose run --rm --no-deps app npm run data -- backup /data/live /backups/backup-20261020
docker compose up -d app
```

替换示例日期，每次使用全新备份目录。只有命令成功、目录中存在 `manifest.json` 才算完成。清单包含数据库及每个对象的 SHA-256；文件不一致时失败，不生成有效清单。

备份含管理员密码哈希、收集令牌、文件内容和已配置模型的凭证主密钥，按私密数据保护。将完整备份目录复制到服务器外：

```sh
mkdir -p ../jiyu-backups
docker compose cp app:/backups/backup-20261020 ../jiyu-backups/backup-20261020
```

把该目录移出项目源码并转存至另一台设备。设置页保留策略仅处理自动命名的完整快照；手动命名的备份由管理员管理。元数据 JSON 和 CSV 不包含文件正文，不能替代完整备份。

## 恢复演练与切换

恢复只能写入全新目录；先验证数据库完整性、清单和每个文件的哈希。不会覆盖现有数据，也不会保留旧登录会话。

```sh
docker compose stop app
docker compose run --rm --no-deps app npm run data -- restore /backups/backup-20261020 /data/restored-20261020
```

成功后，将 `.env` 中 `JIYU_DATA_SUBDIR` 改为 `restored-20261020`，运行 `docker compose up -d app`。使用原管理员密码登录，检查任务并下载文件。旧 `/data/live` 暂时保留，可把配置改回 `live` 回退；确认新数据可用、另有完整备份后再由管理员处理旧目录。恢复需要足够磁盘空间存放新旧两份数据。

## 释放回收站空间

第一版管理页只软删除和恢复，不提供在线永久删除。需要释放空间时，停止应用，运行以下命令。它会先生成新的完整备份；备份成功后才永久清理回收站文件，且必须显式传入确认参数。

```sh
docker compose stop app
docker compose run --rm --no-deps app npm run data -- prune-trash /data/live /backups/before-prune-20261020 --confirm-delete
docker compose up -d app
```

若当前已切换数据目录，替换上面的 `/data/live`。清理后只能通过完整备份恢复，无法从页面恢复。

## 升级

先使用当前版本停机生成完整备份，确认清单有效并另存一份，再 `git pull --ff-only` 和 `docker compose up -d --build`。查看 `/api/health` 或 `docker compose ps`。重启时会清理中断批次的临时对象，已提交文件由数据库引用保护，未完成的模型请求标记为中断。

v0.3 初期从 schema 1 迁移至 2，v0.3.0 使用 schema 4，增加成员、分片、正文索引和远端传输。新备份工具读取旧数据库时不会执行迁移，保留升级前快照；恢复到新目录时才由当前应用迁移。需要回退 v0.2 时，用 v0.2 的程序和恢复工具恢复升级前的 schema 1 备份，不能让旧程序直接打开已迁移的数据目录。未知的更高 schema 会拒绝启动，不自动降级。升级后产生的新数据不在升级前快照中，切换前应另做当前版本完整备份。

## 当前边界

### 远端连接（v0.3.0，schema 4）

页面的「文件已用」统计正式文件与回收站；「收集配额」来自 `JIYU_QUOTA_MB`（默认 10240 MB），这是集屿的接收上限；「数据磁盘剩余」实时读取 `JIYU_DATA_DIR` 所在文件系统。三者含义不同，挂载到 Docker 的数据目录按其所在文件系统报告，不代表容器镜像大小。临时分片、备份及其他应用也会占磁盘。页面每 10 秒刷新并显示读取时间，读取失败会报告不可用，不以零值或旧值冒充成功。

在「添加存储」先选择方式并查看准备条件：WebDAV 需要公网 HTTPS 443 地址、账号与应用密码，S3 需要已建桶及访问凭证；百度 / Microsoft / Google 需要自己的开放平台应用。按页面引导填写后，WebDAV / S3 自动检查，原生网盘在官方页面授权后返回继续检查。检查成功可直接点击「用它创建收集」，新任务会选中此连接。已有任务需手动编辑规则，不会自动迁移历史文件。

夸克已按用户要求移除，包括专用 WebDAV 桥接入口。旧数据仍保留原配置和记录，但旧任务与文件在工作台按本机副本读取，旧队列不再发起该平台请求。

在「存储空间」保存并验证连接后，在新建 / 编辑收集时选择目标。接收回执先代表本机持久化完成，云端同步作为独立队列执行；失败、配置变化或授权过期时保留本机原件并显示错误，可检查连接后重试。**当前保留完整本机副本，不节省 VPS 正文空间**；预览、归档与完整备份继续从该副本读取。云端对象采用任务 ID / 文件 ID 加上传时名称，后续显示名变化不移动云端对象。

| 连接 | 配置与验证 | 验收边界 |
| --- | --- | --- |
| WebDAV | 已存在的公网 HTTPS 443 地址、账号与应用密码；写入随机样本、读回 SHA-256 后删除样本 | 标准协议测试通过，需用户实际服务验证 |
| S3 兼容 | HTTPS 端点、已存在的桶、区域与访问凭证；SigV4，路径式寻址，支持临时 Session Token | 上传与读回校验协议测试通过，未覆盖所有兼容商 |
| 百度网盘 | 自有开放平台应用 API Key / Secret，网盘权限与 `/apps/应用名` 下目录；设备码授权并校验账号 | 4 MiB 分片 MD5 和合并尺寸验证；需具备平台接入资格并实测 |
| OneDrive | 自有 Microsoft OAuth 网页应用 Client ID / Secret，登记页面显示的回调；Files.ReadWrite / offline_access | 原生授权、刷新、分片和读回协议验收，未使用用户账号实测 |
| Google Drive | 自有 Google OAuth 网页应用 Client ID / Secret，启用 Drive API 并登记回调；drive.file | 仅访问本应用创建的文件；原生授权、上传与读回协议验收，待真实账号验证 |

百度应用条件和目录权限以[官方开放平台](https://yun.baidu.com/open/platform)为准；不使用公开样例中的临时体验密钥。Microsoft / Google 授权依据其[授权码协议](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow)和[网页应用授权流程](https://developers.google.com/identity/protocols/oauth2/web-server)。这些连接均需自己的应用资格与用户手动授权，安装集屿不会自动获得网盘访问权限。


连接凭证与刷新令牌使用已有 AES-256-GCM 主密钥加密，不回显到界面。修改连接会撤销原验证状态，旧传输需检查后手动重试；重新授权换账号会更新连接版本，避免旧请求沿用新账号。OAuth 回调校验随机一次性状态、PKCE、发起管理员权限与连接版本；恢复备份会清理未完成授权。平台可能轮换或撤销刷新令牌，恢复后必要时重新授权。

正式目录升级前已生成的旧版备份保留原 schema；本轮增加 schema 4 的连接、授权和传输表，旧程序不能直接打开迁移后的目录。真实 VPS 上线、网盘账号联调与用户模型实测尚需实际运行条件，不在协议测试结果中冒充完成。

v0.3.0 数据库为 schema 4，包含成员、分片上传、正文索引和远端传输。首次升级前仍须停机生成旧版备份，恢复到新目录才迁移。原管理员登录名为 `admin`，密码不变；所有成员共用同一工作台，并非互相隔离的租户。编辑者可收集整理，只读成员可预览下载，只有管理员可配置模型、存储连接、备份和成员。

提交页采用 4 MiB 分片并校验 SHA-256，服务器保存未完成分片 24 小时、预留整批配额。刷新后在同一浏览器填写原姓名并重选原文件，客户端逐片对照已上传哈希；修改了正文的文件不能拼接到旧批次。公开链接更换或任务关闭后，旧续传同样失效。恢复备份会撤销未完成续传；未完成的分片不属于正式收集文件，也不进入完整备份。

正文识别在批量工具或文件详情手动安排，单次最多 50 个，队列串行并可跨重启继续。每文件最多 64 MB，正文索引最多 64,000 字符；PDF 文字前 50 页，扫描 PDF OCR 前 10 页。支持 PDF、DOCX、UTF-8 文本、PNG/JPEG/WebP/GIF，其他类型仍可收集下载。HTML/SVG 不内联执行。识别文字随数据库备份，受本机磁盘权限保护。

Docker 镜像已包含 Poppler 和 Tesseract 简体中文 / 英文模型。本机直接运行需自行安装并加入 PATH，或使用 `JIYU_PDFTOTEXT`、`JIYU_PDFTOPPM`、`JIYU_TESSERACT` 指定可执行文件路径。没有工具会显示明确错误，文本和 DOCX 不依赖这些原生工具。

模型默认只读确认的元数据。助手内可另行勾选「同意发送已识别的正文摘录」，每次明确确认后才发送选定文件最多共 8,000 字符、每份最多 4,000 字符；并不上传原始文件。AI 分类建议与改名一起预览，状态未变且方案未过期时一次应用，可撤销两类修改。

- 已实现本地持久存储、管理员认证、公开提交、下载、校验哈希、批量整理、回收站、离线备份恢复和可配置的模型辅助。
- 远端存储已实现上述协议适配，真实账号待验证；夸克已移除。未配置模型时助手使用本地规则。

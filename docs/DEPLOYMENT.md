# 集屿部署与运维

当前版本为 **v0.5.0**（SQLite schema 6，MIT）。日常部署建议检出对应版本标签或稳定 `main` 提交后构建。

### v0.5.0（SQLite schema 6）升级说明

当前版本使用 SQLite `schema 6`（在 `files` 表增加物化索引列以支持真 SQL 分页筛选，并新增 `webhook_logs` 表；任务定时截止预警配置保存在现有 `collections.data` JSON 中）。升级前请先停止服务，使用当前备份工具生成升级前完整快照，再更新构建并启动；首次打开数据库自动幂等迁移。回退旧版本必须将升级前备份恢复至全新目录，不能让旧版本直接打开 `schema 6` 数据库。

CI 会提取历史 `v0.3.0` 程序在隔离目录生成数据，并在当前 Linux 运行镜像中执行跨版本自动升级、原账号登录、旧文件读取、未完成分片续传及旧版快照回退验证。

空间不足（HTTP 507）时先检查数据磁盘、文件系统配额和备份占用，不要删除数据库、WAL 或未知正文。未取得回执的批次可在释放容量后用原文件重试，已确认分片仍按 24 小时规则保留；若已成功但响应中断，可确认上次提交结果。回收站仍占配额，管理员可在回收站页面执行二次确认在线永久清理，或按本文停机备份流程使用离线 CLI 清理。

登录后在「设置 → 部署检查」可检查数据读写、SQLite、磁盘与接收配额、Origin / HTTPS、备份与原生工具状态。Docker 镜像已内置 Poppler 与 Tesseract（简体中文/英文）；本机直接运行未安装相关工具时会明确提示，不影响普通文件收集。

完整备份包含模板、名单、提交字段、Webhook 加密配置及回执凭证哈希；恢复后保留本人回执查询与 Webhook 解密能力，并撤销旧登录会话、未完成上传与 OAuth 流程。回执明文凭证仅由提交者保管。

适合单台 Linux VPS、单个工作台团队部署。需要 Docker Engine 与 Compose 插件，域名已解析至 VPS，放行 TCP 80/443（可选 UDP 443）。数据库需位于本地文件系统（不放 NFS），单个数据目录仅启动一个应用进程。

## 本机运行

安装 Node.js 24.11+（24.x），在仓库根目录执行：

```sh
npm ci
npm test
npm run build
npm start
```

打开 `http://127.0.0.1:3000`。首次页面需要初始化口令：Windows 执行 `Get-Content data/setup-token`，Linux 执行 `cat data/setup-token`。口令只用于创建管理员，完成后文件自动删除。设置至少 12 字符的密码，妥善保存在密码管理器中；不会生成默认账号或默认密码。原型的浏览器演示数据不会导入。

开发前后端时，在第一个终端将 `JIYU_ORIGIN` 设为 `http://127.0.0.1:5173` 后运行 `npm run server:dev`，第二个终端运行 `npm run dev`。Vite 将 `/api` 代理到 3000；Origin 必须与访问页面完全相同。正式环境用后端直接提供 `dist/`，无需 Vite。

## VPS 部署

```sh
git clone https://github.com/1Beyond1/jiyu.git
cd jiyu
cp .env.example .env
```

编辑 `.env` 中的 `JIYU_DOMAIN` 和 `JIYU_ORIGIN`，例如分别为 `files.example.com` 和 `https://files.example.com`，然后：

```sh
docker compose up -d --build
docker compose ps
docker compose exec app cat /data/live/setup-token
```

打开域名，输入上一步的初始化口令并创建管理员。Caddy 自动申请 HTTPS 证书；应用端口 3000 不映射到公网。不要在 `.env` 中填写管理员密码，也不要把初始化口令发给提交者。初始化后创建收集、分享链接，使用另一台设备验证上传，再从管理端下载检查。

数据位于 Compose 命名卷的 `/data/live`，备份位于独立卷 `/backups`。升级、重建容器保留这些卷。**不要使用 `docker compose down -v`**，它会删除卷。需要迁移服务器时，必须迁移完整备份，不能只复制 Git 仓库。

## 配额与运行限制

| 配置                                                 | 默认                         | 说明                                                                                      |
| ---------------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------- |
| `JIYU_ORIGIN`                                        | 本机 `http://127.0.0.1:3000` | 必须与外部页面地址相同；HTTPS 时启用 Secure cookie                                        |
| `JIYU_QUOTA_MB`                                      | 10240                        | 文件总配额，含回收站，不代表磁盘实际容量                                                  |
| `JIYU_REQUEST_MB`                                    | 512                          | 一次上传的文件正文总量上限；请求封装另有 2 MiB 硬限额                                     |
| `JIYU_DATA_SUBDIR`                                   | `live`                       | Compose 数据卷中的子目录，可切换到已恢复的新目录                                          |
| `JIYU_AI_BASE_URL` / `JIYU_AI_MODEL` / `JIYU_AI_KEY` | 空                           | 预置模型配置，三项都填才生效，用户免配置即可使用 AI；管理员可在设置中改用自己的模型或关闭 |
| `JIYU_AI_PROTOCOL` / `JIYU_AI_DAILY_CALLS`           | `chat` / `50`                | 预置模型接口协议（`chat`/`responses`）与每日调用上限                                      |
| `JIYU_BACKUP_MAX_KEEP`                               | 30                           | 管理员最多可保留的完整备份份数（1–30）                                                    |
| `JIYU_STORAGE_STRICT_READBACK`                       | 空                           | 设为 `1` 时禁用远端原生校验和省流路径，强制重新下载验证 SHA-256                           |
| `JIYU_RATE_LIMIT_GLOBAL`                             | 180                          | 全局每分钟限流次数                                                                        |
| `JIYU_RATE_LIMIT_UPLOAD_MULTIPART`                   | 30                           | multipart 上传每小时限流次数                                                              |
| `JIYU_RATE_LIMIT_UPLOAD_CREATE`                      | 60                           | 分片批次创建每小时限流次数                                                                |
| `JIYU_RATE_LIMIT_UPLOAD_CHUNK`                       | 180                          | 分片上传每分钟限流次数                                                                    |
| `JIYU_RATE_LIMIT_UNLOCK`                             | 6                            | 公开提取码解锁每分钟防爆破限流次数                                                        |
| `JIYU_DATA_DIR`                                      | 本机 `./data`                | 非 Compose 时指定持久数据目录                                                             |
| `JIYU_HOST` / `JIYU_PORT`                            | `127.0.0.1` / `3000`         | 非 Compose 时的监听地址；不直接开放裸 HTTP 到公网                                         |
| `JIYU_TRUST_PROXY`                                   | `false`                      | 仅在应用只允许可信反向代理访问时开启；Compose 内置配置为 `true`                           |

每个任务另有文件格式、单文件大小、单次数量、任务总容量限制。最多同时处理 4 个上传请求，单次最多 100 个文件，文件总数最多 10000（含回收站）。文件正文不整块读入内存。上传请求最多 10 分钟，失败后保留所选文件可重试；同一个提交编号不会重复保存。

登录尝试每来源每分钟最多 5 次；提取码解锁默认每分钟 6 次，并叠加单 IP 指数退避、跨 IP 全局保护与单任务并发在途校验上限。Compose 为 `app` 与 `caddy` 均配置 `cap_drop: [ALL]`、`no-new-privileges:true`、内存与进程数限制；`Caddyfile` 自动注入 `Strict-Transport-Security` 与 `Permissions-Policy` 安全头。日志输出不包含令牌、文件名或密码，Docker 日志轮转为每容器 2×10 MB。

## 批量 ZIP 下载

工作台成员可对选中文件或当前筛选结果生成归档预览，支持平铺、任务、提交人、任务/提交人、材料项/提交人、提交人/材料项 6 种目录结构，并支持严格绑定 `rulesRevision` 的「仅打包人工核对通过（`accepted`）」筛选。下载使用当前显示名称，归档内自动处理非法路径、过长名称、设备保留名和大小写重名，不修改原文件。

## 事件通知（Webhook）与定时截止预警

管理员可在「设置 → 事件通知」配置飞书、钉钉加签、企业微信或通用 HMAC Webhook 渠道。所有目标 URL 强制公网 HTTPS（443 端口）并经 DNS/IP SSRF 校验，URL 与加签密钥经 `secrets.key` AES-256-GCM 加密存储；投递日志自动脱敏并保留最近 50 条。

每个收集任务可在规则中启用**定时截止预警**（提前 24h / 12h / 6h / 1h 与缺交名单脱敏开关）。服务端受单进程锁保护，默认每 5 分钟巡检一次活跃任务，投递成功后原子写入 `lastSentDeadline` 防止重启重复发送；管理员与编辑者也可在材料核对页或提交人台账点击一键推送实时催交摘要。

## 收集模板导入导出

支持在模板管理中导出与导入标准 `jiyu-template-v1` JSON 文件，便于跨工作台复用规则。导出时严格剥离应交名单、截止日期、分享令牌、提取码与存储凭证；导入仅开放给管理员与编辑者并严格校验格式、字段数量与长度上限。

每个归档最多 500 个文件和 10 GiB 原始内容，最多 2 个同时传输；创建预览每来源每分钟 12 次，开始下载 6 次。计划保存在内存，最多 20 个，绑定登录会话，10 分钟内开始且只能使用一次，重启后失效。关闭未开始的预览会清理计划，其他已结束计划最多保留 10 分钟；不生成服务器 ZIP 缓存，也不新增数据库表。

ZIP 按需逐个读取文件并核对 SHA-256，只打包、不重新压缩。浏览器直接接收 HTTP 附件，无需前端把整个包读入内存。传输最多 30 分钟，断开、取消、正文缺失或校验失败时释放资源；开始后不支持断点续传，失败需重新生成预览。服务端「已发送」不代表浏览器已保存到磁盘，最终结果以浏览器下载列表为准。

## 模型服务

默认关闭。在管理员设置页填写模型 ID、HTTPS 接口根地址和 API Key，选择 Responses 或 Chat Completions 协议，保存后启用。服务地址不要包含最终的 `/responses` 或 `/chat/completions`；只接受公网 HTTPS 443，不跟随重定向，DNS 解析到内网或保留地址会拒绝。VPS 需允许外部 DNS 与 HTTPS 出站。兼容服务必须支持相应 JSON 输出及输出长度参数，不保证所有兼容商的所有模型都能直接使用。

Key 经 AES-256-GCM 加密保存于 SQLite；随机主密钥位于数据目录 `secrets.key`（Linux 权限 0600），首次保存凭证时生成。不要只备份数据库、单独删除此文件或公开完整备份。备份工具自动复制并校验主密钥，恢复后可继续使用原凭证；缺失时需从完整备份恢复或在设置页重新填写 Key。移除凭证会同时停用模型。

连接测试明确调用一次模型，不发送文件信息，计入次数并可能计费。悬浮面板的每次提问需要确认发送：当前问题、工作台统计，以及最多 30 个选定文件的名称、大小和任务名；提交人默认不发送，需另行勾选。上传令牌与整段历史不会进入模型上下文；正文默认不发送，额外授权的摘录范围见下文。更换服务商必须重新填写 Key；设置变更使旧的发送授权失效。

每次问题最多 1000 字符，最多 2 个同时处理的模型请求；提问每来源每分钟 6 次、测试连接 3 次。默认每天 50 次调用（可设 1–1000），按 UTC+8 重置，失败和取消也计入。DNS 解析最多 5 秒，HTTP 请求最多 45 秒，响应最多 128 KiB。取消不能保证服务商停止计费，次数限制也不等于金额预算，需在服务商账户另设费用上限。

模型只能返回建议。命名方案经过服务端检查，预览确认后才执行，30 分钟有效且只能应用一次；文件状态或名称已变化时会拒绝，成功后可撤销。调用历史仅保留模型、文件数量、状态、用量与时间，不保存问题和回复正文；本机面板关闭后不保留对话。该限制不控制服务商自身的数据保留政策。

## 完整备份

日常可在设置页直接执行在线完整备份，并设置每 6 / 12 / 24 小时或每周自动备份，保留最近 1–30 份。默认关闭自动计划，避免未经配置占满磁盘。Compose 将备份写到独立 `/backups` 卷；直接运行 Node 可通过 `JIYU_BACKUP_DIR` 指定，否则使用数据目录旁的 `backups/`。新快照校验成功后才执行保留策略，手工命名的其他备份不在自动清理范围。

在线备份使用 SQLite 快照中的对象引用复制不可变正文，正文、数据库和凭证主密钥都校验。备份执行期间继续接收上传；新上传若不在该快照内，会进入下一份备份。下面的停机命令仍用于升级前快照与运维。

先停止应用，生成数据库与文件一致的完整快照；Caddy 可以继续运行。备份命令检测数据目录互斥锁，在线运行会拒绝。

```sh
docker compose stop app
docker compose run --rm --no-deps app npm run data -- backup /data/live /backups/backup-20261020
docker compose up -d app
```

替换示例日期，每次使用全新备份目录。只有命令成功、目录中存在 `manifest.json` 才算完成。清单包含数据库及每个对象的 SHA-256；文件不一致时失败，不生成有效清单。

备份含管理员密码哈希、收集令牌、文件内容和已配置模型的凭证主密钥，按私密数据保护。将完整备份目录复制到服务器外：

```sh
mkdir -p ../jiyu-backups
docker compose cp app:/backups/backup-20261020 ../jiyu-backups/backup-20261020
```

把该目录移出项目源码并转存至另一台设备。设置页保留策略仅处理自动命名的完整快照；手动命名的备份由管理员管理。元数据 JSON 和 CSV 不包含文件正文，不能替代完整备份。

## 恢复演练与切换

恢复只能写入全新目录；先验证数据库完整性、清单和每个文件的哈希。不会覆盖现有数据，也不会保留旧登录会话。

```sh
docker compose stop app
docker compose run --rm --no-deps app npm run data -- restore /backups/backup-20261020 /data/restored-20261020
```

成功后，将 `.env` 中 `JIYU_DATA_SUBDIR` 改为 `restored-20261020`，运行 `docker compose up -d app`。使用原管理员密码登录，检查任务并下载文件。旧 `/data/live` 暂时保留，可把配置改回 `live` 回退；确认新数据可用、另有完整备份后再由管理员处理旧目录。恢复需要足够磁盘空间存放新旧两份数据。

## 释放回收站空间

管理员可在工作台「回收站」页直接对已软删除文件执行二次确认的在线永久清理（系统会自动校验活跃 ZIP 打包、在线备份、云端传输与正文识别状态，防止并发误删）。如需在清理前强制先做一次停机完整快照，也可停止应用后运行离线命令：

```sh
docker compose stop app
docker compose run --rm --no-deps app npm run data -- prune-trash /data/live /backups/before-prune-20261123 --confirm-delete
docker compose up -d app
```

若当前已切换数据目录，替换上面的 `/data/live`。永久清理后只能通过完整备份恢复，无法从页面找回。

## 升级

先使用当前版本停机生成完整备份，确认清单有效并另存一份，再拉取代码并执行 `docker compose up -d --build`。启动后检查 `/api/health`（应返回 `version: "0.5.0"`）或 `docker compose ps`。

数据库已演进至 `schema 6`（含成员、分片续传、正文索引、远端传输、模板、提交记录、物化分页索引与 Webhook 日志）。新备份工具读取旧数据库时不会执行迁移，保留升级前快照；恢复到新目录时才由当前应用迁移。回退旧版本需恢复对应升级前快照至全新目录，未知更高 schema 会拒绝启动。

## 远端存储与运行边界

### 远端连接与成员权限

页面的「文件已用」统计正式文件与回收站；「收集配额」来自 `JIYU_QUOTA_MB`（默认 10240 MB）；「数据磁盘剩余」实时读取 `JIYU_DATA_DIR` 所在文件系统。

在「存储空间」保存并验证连接后，可在新建/编辑收集时选择目标。支持 WebDAV、S3/兼容存储，以及百度网盘、OneDrive、Google Drive 官方 OAuth 协议；OAuth Token 刷新具备按平台单飞锁防止并发轮换失效，瞬态网络故障支持指数退避自动重试。所有文件均先在本机落盘并保留完整副本用于在线预览、打包与备份。

| 连接         | 配置与验证                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------------- |
| WebDAV       | 公网 HTTPS 443 地址、账号与应用密码；写入随机样本、读回 SHA-256 后删除样本                     |
| S3 兼容      | HTTPS 端点、存储桶、区域与访问凭证；SigV4，支持 `x-amz-checksum-sha256` / 单段 MD5 校验        |
| 百度网盘     | 自有开放平台应用 API Key / Secret，`/apps/应用名` 目录；设备码授权，4 MiB 分片 MD5 校验        |
| OneDrive     | 自有 Microsoft OAuth 网页应用（PKCE），`Files.ReadWrite` / `offline_access`，优先核验原生 Hash |
| Google Drive | 自有 Google OAuth 网页应用（PKCE），`drive.file`，优先核验 `sha256Checksum`                    |

所有成员共用同一工作台：`admin` 可管理成员、模型、Webhook、存储连接、备份、永久清理与线下补录；`editor` 可创建/管理收集、核对材料、导入导出模板与推送催交摘要；`viewer` 可浏览、预览与打包下载。

提交页采用 4 MiB 分片并校验 SHA-256，服务器保留未完成分片 24 小时并在清理孤立分片时执行实时活跃校验与宽限期保护。正文识别单次最多 50 个文件（单文件 ≤ 64 MB，索引 ≤ 64,000 字符；PDF 前 50 页，扫描 PDF OCR 前 10 页）；Docker 镜像已内置 Poppler 与 Tesseract，本机运行可通过 `JIYU_PDFTOTEXT`、`JIYU_PDFTOPPM`、`JIYU_TESSERACT` 指定路径。

- 接受格式按扩展名校验，预览另按文件头限定类型，不内联执行 HTML/SVG 或文档脚本。
- 生产环境需自行配置域名、HTTPS、访问控制与异地备份（项目不含病毒扫描或端到端加密）。
- Node.js 24 运行时请在升级前先完成备份与恢复演练。
